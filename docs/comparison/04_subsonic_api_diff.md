# Совместимость с Subsonic API, расширения и дифференциал эндпоинтов

Исчерпывающий сравнительный анализ протокольной совместимости с **Subsonic REST API**, реестр поддерживаемых и неподдерживаемых методов, расширения **OpenSubsonic** и проприетарные API обоих проектов.

---

## 1. Заявляемые версии протокола Subsonic REST API

- **Airsonic Advanced (наш форк):** Заявляет версию **`1.15.0`** (зафиксировано в `subsonic-rest-api.xsd` и классе ответа `Response.kt`).
  - *Архитектурное примечание:* Клиентские приложения, жестко требующие спецификацию `1.16.x` без проверки обратной совместимости, могут получать ошибку `Error Code 30: PROTOCOL_MISMATCH_SERVER_TOO_OLD`.
- **Navidrome:** Заявляет версию **`1.16.1`** (константа `const Version = "1.16.1"` в `server/subsonic/api.go`).
  - Обеспечивает максимальную совместимость с самыми современными клиентами (Symfonium, DSub, Tempo, substreamer, Amperfy, Ultrasonic).

## 3. Различия в форматах ответов и кодах ошибок

### 3.1. Форматы сериализации (XML, JSON, JSONP)
- **Airsonic Advanced:**
  - XML формируется через явные Kotlin DTO с аннотациями Jakarta XML Binding (JAXB / MOXy). Корневой элемент: `<subsonic-response xmlns="http://subsonic.org/restapi" status="ok" version="1.15.0">`.
  - JSON формируется через Jackson JAXB-annotations с корневым ключом `"subsonic-response"`.
  - JSONP поддерживается при наличии параметра `callback` (значение валидируется regex).
- **Navidrome:**
  - XML генерируется стандартным пакетом Go `encoding/xml`. Корневой элемент содержит аналогичный namespace и версию `1.16.1`.
  - JSON сериализуется стандартным `encoding/json`.
  - Строгая валидация JS-идентификатора для `callback` в JSONP (`^[a-zA-Z_$][a-zA-Z0-9_$.]*$`).

### 3.2. Стратегия HTTP-статусов при ошибках
- **Airsonic:** Строго придерживается классической логики Subsonic: **всегда возвращать HTTP статус `200 OK`**, а саму ошибку помещать в тело ответа в тег `<error code="..." message="..."/>`.
- **Navidrome:** В целом следует спецификации Subsonic (HTTP 200 с `<error>`), но активно использует современные HTTP коды для семантического информирования клиентов:
  - `HTTP 410 Gone`: для намеренно вырезанных эндпоинтов (`search`, `getVideos`, `getChatMessages`).
  - `HTTP 501 Not Implemented`: для эндпоинтов, от которых сервер отказался (`createUser`, `getPodcasts`).
  - `HTTP 429 Too Many Requests`: при превышении максимального числа одновременных процессов `ffmpeg` (`ErrTooManyTranscodes`), сопровождается заголовком `Retry-After: 5`.
