# Аудит покрытия прежних HTTP endpoints новым Ktor API

Дата аудита: 23 ноября 2026 г.

## Результат

Старые Spring MVC/servlet HTTP handlers в текущих production-исходниках отсутствуют. Ktor API зарегистрирован отдельно под `/api/v1`, использует bearer-сессии и собственные JSON DTO. Старые `/rest`, XML/JSONP и клиентские `u/p`/`t/s` контракты не сохраняются.

Сравнение сделано с последним состоянием REST controller tree до удаления Subsonic слоя (`c0cc6c0^`) и текущей регистрацией `standaloneModule`/Ktor route classes. Совпадение формы и параметров старых запросов намеренно не считается целью.

## Сверка удалённых контроллеров по семействам

Имена ниже относятся к старым классам, а не к обязательным именам новых Ktor-классов. Удалённый контроллер считается заменённым, если его поддерживаемые действия доступны через указанные Ktor routes и покрыты поведением, даже когда маршрут спроектирован иначе.

Старые Ktor adapter-файлы `KordinatorAuthRoutes`, `KordinatorArtistRoutes`, `KordinatorSearchRoutes`, `KordinatorPlaylistRoutes`, `KordinatorTrackRoutes`, `album/AlbumRoutes.kt` (ранее `KordinatorAlbumRoutes.kt`), `album/AlbumSummary.kt` и `album/AlbumDetails.kt` физически удалены коммитом `082b0f2`, потому что сами эти классы не были подключены к production `standaloneModule`. Их действующие маршруты находятся inline в `KtorApplication.kt` и используют production services; отдельные production route classes, например `KordinatorPlaylistImportRoutes`, остались подключены. В ходе повторной сверки восстановлены ранее отсутствовавшие album details (`year`, `genre`, `trackCount`) и artist details (`albumCount`, `albums`) в активных JSON-ответах. Старые тесты удалённых adapter-классов не считались проверкой production API; соответствующие active routes проверяются через `KtorStandaloneRealScanIsolationTest` и другие integration tests ниже.

## Выявленные расхождения и решения

| Старый сценарий | Текущее состояние | Следствие |
|---|---|---|
| Универсальный `getCoverArt` по media-file, album, artist и playlist ID | Есть `/tracks/{id}/artwork`, `/albums/{id}/artwork`, `/artists/{id}/artwork`, `/playlists/{id}/artwork`; у всех поддерживаются GET/HEAD | Обложки ищутся в папке трека, затем в embedded artwork, затем берётся default cover. Доступ к альбомам/исполнителям ограничен library scope, к плейлистам — владельцем, публичной видимостью или reader grant, а сами треки остаются ограничены library scope. Интеграционные проверки: `KtorStandaloneRealScanIsolationTest`. |
| `getAlbumList` и `getAlbumList2` — режимы списка альбомов | `GET /albums?sort=name|artist|year|newest|most-played|recently-played|random|highest-rated`, фильтры `genre`, `fromYear` и `toYear`; избранные альбомы вынесены в `GET /favorites/albums` | Поддержанные режимы используют core каталог и учитывают bearer library scope, пагинацию и отфильтрованный `total`. `GET/PUT /albums/{id}/rating` сохраняют персональные оценки альбомов в standalone DB; `highest-rated` сортирует по их среднему значению и не раскрывает оценки других пользователей. Случайная сортировка учитывает диалект HSQLDB, H2, PostgreSQL и MySQL/MariaDB. `KtorStandaloneRealScanIsolationTest` проверяет фильтры жанра/года, порядок, случайную выборку, сохранение/чтение оценок, сортировку по среднему рейтингу, счётчик и изоляцию между библиотеками. |
| `getAlbumInfo*` и `getArtistInfo*` как отдельные сущности | `/tracks/{id}/metadata`, `/albums/{id}/metadata`, `/artists/{id}/metadata` | Независимые маршруты используют те же Last.fm метаданные и проверяют library scope. Интеграционные проверки: `KtorStandalonePlaylistTest`. |
| `getIndexes` и просмотр директорий | Каталог предоставляет `/libraries`, `/library/folders`, `/library/folders/{id}`, `/library/directories/{id}` и `/artists?prefix={text}` | `KordinatorLibraryRoutes` подключён в production `standaloneModule` внутри bearer-auth группы. Доступ к корневым папкам и вложенным директориям проверяется по `LocalUserPrincipal.allowedLibraryIds`; в текущей модели эти значения — `MusicFolder.id`, те же ID используются администрацией библиотек и core-каталогом. `/artists` отсортирован и поддерживает literal prefix для быстрого перехода к нужной части списка; поиск по префиксу также учитывается в total. Отдельный Subsonic-подобный список буквенных корзин не нужен новому JSON API. Предыдущее утверждение этого аудита, что `KordinatorLibraryRoutes` не подключён и проверяет legacy-пользователей, было ошибочным. |
| Поиск и установка внешней обложки (`searchCoverArt`, `setCoverArt`) | `GET /api/v1/artwork/search`, `PUT /api/v1/library/directories/{id}/artwork/from-search`, `PUT /api/v1/library/directories/{id}/artwork` | Поиск через Last.fm принимает исполнителя, альбом или оба поля; выбранный адрес можно сохранить только если он является точным результатом этого поиска и находится на разрешённом HTTPS-хосте Last.fm. Также доступна прямая загрузка JPEG/PNG/GIF. Сохранение ограничено администратором, размером 20 MiB, проверкой содержимого/размеров изображения и корнем библиотеки. Покрыто `KtorStandaloneArtworkTest` и `StandaloneArtworkServiceTest`. |
| Podcast channels, episodes, settings, download/refresh, Podcast REST actions | Не имеют Ktor routes; код, модели, DAO и сервисы удалены в `56494f2`; REST handlers ранее помещались в quarantine/removal | По решению пользователя 23 ноября 2026 года остаётся вне проекта. Не редактировать архивный код и не восстанавливать subsystem/контракт. `drop-podcasts.xml` переводит podcast media в MUSIC, удаляет podcast folders и таблицы episodes/channels/rules без rollback; это историческое удаление данных, не перенос. |
| Internet-radio settings, station CRUD и список станций | Не имеют Ktor routes; сервисы, DAO, модели и UI удалены в `300688c` | По решению пользователя 23 ноября 2026 года остаётся вне проекта; Ktor API и новое хранение не добавлять. `drop-internet-radio.xml` удаляет таблицу `internet_radio` без rollback; это историческое удаление данных, не перенос. |
| Общий `/proxy` endpoint | Не имеет общего Ktor аналога | Удалён отдельным `5c2e829` после записи использования legacy endpoint в `7d0bc59`. В продуктовый объём не входит произвольная прокси-загрузка; нужный сценарий поиска обложек реализован отдельным Last.fm-сервисом с проверкой источника. |
| Media-file comment endpoint | Не имеет Ktor route | Удалён как obsolete в `563d96c`. API предоставляет приватные заметки владельца через `/tracks/{id}/note`; прежнее общее поле комментария в каталоге намеренно не переносится. |
| `getLicense`, XML/JSONP, `.view`, Subsonic `u/p` и `t/s` | Удалены | Соответствует принятому решению отказаться от Subsonic совместимости. |

Этот аудит сравнивает поведение, а не совпадение старых URL/параметров. Перенос нельзя считать завершённым только из-за отсутствия Spring/servlet-контроллеров: маршруты должны быть подключены в standalone Ktor pipeline, использовать новую bearer-модель доступа и иметь проверки поведения. Podcast и internet-radio исключены из продуктового объёма по решению пользователя от 23 ноября 2026 года; старые миграции удаления их данных задокументированы отдельно и не считаются переносом. Общий proxy и общий комментарий не входят в новый продуктовый объём; приватные заметки трека являются отдельной функцией. `getLicense`, XML/JSONP, старые auth-параметры и JSP-контракты заменены новой bearer/API моделью или явно удалены по принятым решениям.

## Проверки источников

- Нет Spring MVC mapping annotations, `HttpServlet` handlers или `@WebServlet` в активном `airsonic-main/src/main/java`.
- Текущий source scan production source не обнаружил Spring API, Servlet API, Tomcat, Spring application bootstrap или MVC annotations; Maven `dependency:tree` с runtime-фильтрами `org.springframework`, `javax.servlet`, `jakarta.servlet` и `org.apache.tomcat` не нашёл зависимостей.
- Упакованный `kordinator.jar` не содержит классов `org.springframework`, Servlet API или Tomcat.
- Production Ktor registration находится в `KtorApplication.kt`; active route classes are called there within `standaloneModule` and its bearer-authenticated route groups.
- `subsonic-rest-api`, JAXB response mapper и `JAXBWriter` удалены; production API DTO находятся в Ktor пакете.
- Main class shaded JAR — `org.airsonic.player.ktor.KtorApplicationKt`; он запускает `embeddedServer(Netty)` напрямую. История содержит отдельные срезы `6438f35` (удаление servlet bootstrap), `e623073` (удаление Spring Boot/Tomcat launch path) и `1db2296` (упаковка standalone Ktor JAR).
- Проверка packaged JAR обнаружила и исправила передачу `--airsonic.home` старым сервисам через JVM property. С исправлением jar запущен без Spring/servlet host: `GET /api/v1/health` вернул `200 {"status":"UP"}`, а старый `/rest/getLicense` вернул `404`.
- Maven `package -DskipTests` прошёл; `RuntimeConfigurationLoaderTest` и `KtorStandaloneModuleTest` прошли 22/22. Портовый smoke запуск делался на loopback и изолированном `/tmp` home; сервер завершён graceful shutdown.
- После срезов импорта legacy playlists/avatars повторно прошёл `mvn -o -f airsonic-main/pom.xml -Dcheckstyle.skip=true -Dpmd.skip=true -DskipTests package`. Обновлённый `target/kordinator.jar` запущен на изолированном `/tmp` home: `/api/v1/health` вернул `200 {"status":"UP"}`, `/rest/getLicense` вернул `404`; manifest указывает `KtorApplicationKt`, jar не содержит Spring/Servlet/Tomcat классов. Для этого runtime smoke потребовался loopback bind вне sandbox. Docker и Podman в текущем окружении отсутствуют; контейнерный build здесь не подтверждён.
- После удаления неиспользуемых route adapters `mvn -Pdocker -pl install/docker -am -DskipTests -Ddocker.skip=true package` успешно собрал Maven reactor и подготовил `install/docker/target/dependency/airsonic-main.jar`, побайтно совпадающий с `airsonic-main/target/kordinator.jar`. В окружении нет `docker`/`podman`, поэтому сам image build/Container smoke не выполнялся.
- После восстановления обложек в offline Maven прогоне прошли 76 Ktor/standalone tests; изолированный `KtorStandaloneScanTest` был повторно прогнан с разрешением на loopback и тоже прошёл. PMD отключался из-за уже известных ошибок обработки исходников; Kotlin-компиляция и Surefire завершились успешно.
- Catalog browse validation: `KtorStandaloneRealScanIsolationTest` passed with prefix results, literal `%` escaping, pagination totals, and per-library visibility checks.
