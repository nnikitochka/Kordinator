# Акцентный цвет обложек (расширение Subsonic REST API)

Этот документ описывает расширение API, с помощью которого **внешние клиенты** (DSub, Symfonium, play:Sub и любые другие) могут получить **доминирующий цвет обложки** трека, каталога или альбома — например, чтобы подкрашивать интерфейс (фон страницы альбома, подложка «сейчас играет», прогресс-бары) под обложку.

Расширение не входит в стандартный Subsonic/OpenSubsonic API: поле **опциональное**, и клиенты, которые о нём не знают, просто его игнорируют.

## Формат значения

- Строка `#RRGGBB` — шестнадцатеричные цифры в верхнем регистре, например `#A58866`.
- Заполняется только при наличии обложки; в остальных случаях поле **отсутствует** в ответе.

## Где появляется

Необязательный атрибут `accentColor` добавлен к трём типам ответа:

| Тип | Чей цвет возвращается |
|-----|------------------------|
| `Child` | Для трека — цвет обложки **родительского каталога** (так же, как атрибут `coverArt`). Для каталога — цвет его собственной обложки. |
| `Directory` | Цвет обложки самого открываемого каталога. |
| `AlbumID3` | Цвет обложки альбома. |

Типы `NowPlayingEntry` и `AlbumWithSongsID3` наследуют соответственно `Child` и `AlbumID3`, поэтому поле присутствует и в них.

### Эндпоинты

Поле `accentColor` отдаётся во всех ответах, содержащих эти типы:

- `Child`/`NowPlayingEntry`: `getIndexes`, `getMusicDirectory` (элементы `child`), `getAlbum`, `getSong`, `getPlaylist`, `jukeboxControl`, `getAlbumList`, `getRandomSongs`, `getVideos`, `getNowPlaying`, `getSongsByGenre`, `getSimilarSongs`, `getSimilarSongs2`, `getTopSongs`, `search`, `search2`, `search3` (треки).
- `Directory`: `getMusicDirectory` (сам каталог).
- `AlbumID3`: `getArtist`, `getAlbum`, `getAlbumList2`, `search3` (альбомы).

## Примеры

XML (`getMusicDirectory`):

```xml
<subsonic-response xmlns="http://subsonic.org/restapi" status="ok" version="1.15.0">
  <directory id="42" name="Sackcloth 'n' Ashes" accentColor="#A58866">
    <child id="43" title="Black Bush" isDir="false" accentColor="#A58866"/>
  </directory>
</subsonic-response>
```

JSON (тот же запрос с `f=json`):

```json
{
  "subsonic-response": {
    "directory": {
      "id": "42",
      "name": "Sackcloth 'n' Ashes",
      "accentColor": "#A58866",
      "child": [
        {"id": "43", "title": "Black Bush", "isDir": false, "accentColor": "#A58866"}
      ]
    }
  }
}
```

## Как вычисляется цвет

- Используется доминирующий цвет изображения обложки (библиотека color-thief, `ColorThief.getColor`).
- Источник обложки тот же, что и для атрибута `coverArt`: встроенное изображение из тегов аудиофайла либо файл-обложка из папки альбома.
- Цвет вычисляется **один раз** при создании или обновлении обложки (первое сканирование библиотеки, ручная установка обложки, смена обложки) и сохраняется в базе данных. При повторном сканировании той же обложки цвет не пересчитывается.

## Когда поле отсутствует

Клиент должен считать отсутствие `accentColor` нормальным и использовать свой цвет по умолчанию. Поле может отсутствовать, если:

- у элемента нет обложки;
- обложка задана вручную или переопределена **до** появления этого механизма (цвет для неё ещё не посчитан);
- изображение не удалось прочитать/декодировать;
- библиотека не пересканировалась после обновления сервера.

## Совместимость

- Атрибут опциональный, добавляется к уже существующим типам — клиенты без поддержки расширения корректно работают без изменений.
- JSON-клиенты получают дополнительное поле, XML-клиенты — дополнительный атрибут. Строгая валидация ответа по канонической XSD Subsonic не требуется на практике ни одним клиентом, но формально расширение нарушает схему.
