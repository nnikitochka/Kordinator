## 1. Архитектурный стек и потребление ресурсов

- **Airsonic Advanced:**
  - Платформа: Java 17/21/25 + Kotlin 2.x, JVM HotSpot. В данный момент находится на критическом этапе эволюции: постепенная ликвидация Spring Boot, Tomcat 10 и JSP с переходом на асинхронный сервер **Ktor 3.x** и Kotlin Coroutines.
  - Потребление ресурсов: Базовое потребление RAM — **400–800 МБ** в простое, до **1.5–3.0 ГБ** во время сканирования и транскодирования (давление на кучу JVM мусорными объектами JAudioTagger).
  - Холодный старт: **25–60 секунд** (сканирование classpath, рефлексия Spring, миграции Liquibase).
- **Navidrome:**
  - Платформа: Go 1.23, монолитный скомпилированный нативный бинарник без виртуальной машины. Статический Dependency Injection через Google Wire на этапе сборки (0% рефлексии).
  - Потребление ресурсов: **35–65 МБ RAM** в простое, до **150–350 МБ** под нагрузкой. Возможность выноса сканирования в изолированный подпроцесс (`DevExternalScanner`), память которого после завершения возвращается ядру ОС.
  - Холодный старт: **150–400 миллисекунд** (< 0.5 секунды).

## 2. Философия работы с медиатекой: Read-Only vs Read-Write

- **Airsonic Advanced (Read-Write):** Полнофункциональный медиаменеджер. Поддерживает редактирование тегов прямо в файлах на диске (`TagEditController.kt`), вшивание обложек в аудиофайлы, загрузку новых треков через REST API (`UploadController.kt`) и удаление файлов с диска. Позволяет администрировать коллекцию удаленно, но требует прав на запись и несет риск повреждения оригинальных файлов при сбоях.
- **Navidrome (Строгий Read-Only):** Музыкальная библиотека неприкосновенна. Сервер принципиально не содержит ни одной строки кода для записи тегов или удаления аудиофайлов. Рекомендуемый режим работы — монтирование диска с флагом `:ro`. Все пользовательские аннотации сохраняются только в базе данных.
- **Движки сканирования:** Navidrome использует C++ **TagLib** (в 3–8 раз быстрее Java JAudioTagger). Инкрементальное сканирование 50 000 треков в Navidrome занимает **2–5 секунд**, в Airsonic — около минуты.
- **Идентификаторы треков:** Navidrome внедрил детерминированные **Persistent IDs (PID)** на базе хеша метаданных `(artist, album, disc, track, title)` или MusicBrainz ID. Переименование файлов или перемещение между каталогами не сбрасывает лайки, историю и плейлисты. В Airsonic ID привязаны к путям файлов.

## 4. Совместимость с Subsonic API и эндпоинты

- **Заявляемые версии:** Navidrome заявляет **`1.16.1`**, Airsonic Advanced заявляет **`1.15.0`**.
- **Управление пользователями:** Navidrome намеренно возвращает `HTTP 501 Not Implemented` для `createUser`, `updateUser`, `deleteUser`, `changePassword`, требуя управления через Web UI или CLI. Airsonic поддерживает полный цикл администрирования через REST API.
- **Устаревшие функции:** Navidrome возвращает `HTTP 410 Gone` для `search` (v1.0), `getChatMessages`, `addChatMessage`, `getVideos`, `getVideoInfo`, `getCaptions`, `hls`. Airsonic сохраняет их работоспособность.
- **Расширения OpenSubsonic:** Navidrome сообщает о поддержке `transcodeOffset`, `formPost`, `songLyrics` (v1/v2), `indexBasedQueue`, `transcoding`, `playbackReport`, `topSongsByArtistId`, `apiKeyAuthentication`, `sonicSimilarity`.
- **Эксклюзивные расширения нашего форка:**
  - `/rest/kord/vibe/next` — умный радиопоток «Моя волна» с 3 осями фильтрации (настроение, характер, язык);
  - `/rest/kord/lyrics/{id}` — отдача синхронизированных караоке-текстов (.lrc);
  - `/rest/kord/dislike` — регистрация дизлайков для исключения треков из алгоритма волны;
  - Атрибут `accentColor` — HEX-цвет обложки (`#RRGGBB`) в ответах `Child`, `Directory`, `AlbumID3`.

## 5. Транскодирование и стриминг

- **Конвейер запуска:**
  - Airsonic: динамическая сборка команд из БД (`transcoding2`) с подстановкой переменных `%s`, `%b`, `%o`.
  - Navidrome: жестко закодированный вызов `ffmpeg` со строгим маппингом `-map 0:a:0` (защита от кодирования видеопотока обложек), входным сиком `-ss <offset>` перед `-i` (старт за миллисекунды) и безопасным выставлением сэмплов `-sample_fmt` только для FLAC.
- **Патчинг заголовков FLAC:** Navidrome на лету перехватывает первые 26 байт потока и пересчитывает `total_samples` в блоке `STREAMINFO`. Это предотвращает баг мобильных плееров, считающих FLAC-стрим бесконечным радиовещанием.
- **Кэширование потока (Transcoding Cache):**
  - **В Airsonic кэш транскодирования отсутствует.** Каждый повтор трека или запрос другим пользователем запускает новый процесс FFmpeg на 100% CPU.
  - **В Navidrome встроен дисковый LRU кэш (`TranscodingCache`).** Повторные запросы отдаются моментально как статические файлы с нулевой нагрузкой на процессор и мгновенной перемоткой по Range HTTP 206.

## 6. База данных и схемы хранения

- **СУБД:** Airsonic поддерживает внешние PostgreSQL и MySQL/MariaDB (помимо встроенной HSQLDB). Navidrome работает исключительно с файлом SQLite 3 в режиме WAL.
- **Нормализация пользовательских данных:**
  - Airsonic хранит лайки и историю в разрозненных таблицах (`starred_media_file`, `starred_album`, `starred_artist`, `user_rating`, `bookmark`), что требует множественных `JOIN` при генерации списков.
  - Navidrome сводит все действия в единую компактную таблицу `annotation` с покрывающими индексами.
- **Полнотекстовый поиск:** Airsonic использует отдельный индекс Apache Lucene на диске (риск рассинхронизации при сбоях). Navidrome использует встроенный SQLite FTS5 (транзакционная целостность с базой данных).

---

## 7. Безопасность и авторизация

- **Аутентификация:** Оба проекта поддерживают Subsonic Token+Salt (`md5(pass+salt)`). Navidrome поддерживает долгоживущие `apiKey` (`nds_...`) и JWT в веб-интерфейсе.
- **SSO и внешняя авторизация:** Airsonic содержит нативный коннектор к корпоративным серверам LDAP / Active Directory. Navidrome использует Reverse Proxy Header Auth (Forward Auth через Authelia, Authentik, Keycloak).
- **Разграничение прав:** Airsonic предоставляет максимальную гранулярность (12 индивидуальных ролей, лимиты битрейта и папочный RBAC с изоляцией каталогов для конкретных пользователей). Navidrome использует упрощенную модель (`IsAdmin` + доступ к библиотекам).
- **Защита от перебора:** Navidrome имеет встроенный middleware `httprate` для rate-limiting попыток входа.

## 8. Веб-интерфейс и клиентская стратегия

- **Airsonic:** Устаревший JSP-слой (53 страницы) признан балластом и готовится к полному удалению. Сервер трансформируется в headless-бэкенд для нативного Compose Multiplatform клиента **Youamp / Kord** (десктоп и мобильные ОС), обладающего лучшим в классе UX (интерфейс в островном стиле «Floating Islands», плавные эквалайзеры, полноэкранный караоке-плеер, оффлайн-кэш).
- **Navidrome:** Развивает встроенный клиентский Single Page Application (React, TypeScript, Material-UI) с поддержкой PWA (установка на экран смартфона с Service Worker) и эмуляцией MediaSession API.

## 9. Ключевые рекомендации для нашего форка Airsonic

1. **Внедрить дисковый кэш транскодирования (Transcoding Cache):**
   Реализовать `TranscodeCacheService` в Airsonic для сохранения сгенерированных потоков на диск. Это снизит нагрузку на CPU сервера при повторных воспроизведениях до нуля.
2. **Перенести позиционирование `-ss` перед `-i` в шаблонах ffmpeg:**
   Обеспечит мгновенный старт воспроизведения трека при перемотке.
3. **Реализовать патчинг заголовков FLAC (`flac_streaminfo`):**
   Интегрировать перезапись `total_samples` в `TranscodeInputStream.kt` для восстановления перемотки FLAC в мобильных плеерах.
4. **Перейти к детерминированным Persistent IDs (PID):**
   Отвязать `media_file.id` от пути файла на диске, используя хеш от метаданных или MBID. Это защитит плейлисты и лайки пользователей от сброса при переименовании папок.
5. **Поддержать формат Smart Playlists (NSP JSON AST):**
   Внедрить движок динамических выборок по правилам, совместимый с Navidrome.
6. **Завершить переход на чистый Ktor:**
   Окончательный вывод Spring Boot и встроенного Tomcat позволит нашему форку сравняться с Navidrome по скорости старта и потреблению памяти, сохраняя при этом уникальные преимущества (DLNA, видео, Read-Write, «Моя волна»).
